# mc-tunnel — обход блокировок через настоящий Minecraft-сервер

Транспорт, который прячет пользовательский трафик внутри нативных
plugin-message пакетов реального Minecraft-сервера. Для DPI это выглядит как
обычный модовый клиент, подключённый к живому серверу.

> **Статус: milestone 1 — ядро транспорта.** Протокольные примитивы,
> мультиплексор и шейпер написаны и покрыты тестами (`go test ./...` — зелёный,
> включая `-race`). Live-клиент и серверный плагин — рабочий каркас, который
> требует проверки против живого сервера. Это не готовый к бою продукт: см.
> «Честные ограничения» и «Дорожную карту».

## Зачем это и против чего

Цель — доступ в интернет из страны, где файрвол (например, ТСПУ-класса)
фингерпринтит и блокирует сами VPN-протоколы: OpenVPN, WireGuard, Shadowsocks,
а теперь и VLESS+Reality. Когда блокируют протокол, помогает не ещё один
протокол, а трафик, неотличимый от легитимного приложения.

У цензора два разных механизма — и им нужны два разных ответа:

| Механизм цензора | Что его бьёт |
|---|---|
| Активное зондирование, блок-листы IP/подсетей | **Настоящий сервер** с аптаймом, игроками и историей. Пробник упирается в реальный Minecraft-сервер; без ключа канал молчит, как при несовпадении версии мода. |
| Пассивный статистический DPI (размеры/тайминги пакетов) | **Шейпинг трафика** под профиль геймплея (пакет `shape`). |

Ни одно из двух по отдельности не работает. «Реальный сервер» не прячет
статистику потока; шейпинг не спасает, если IP уже в блок-листе. Продукт
совмещает оба.

## Архитектура

```
  приложение → SOCKS5 → [mctun-client] → mux → shape → custom-payload пакеты
                                                              │
                                                     Minecraft-протокол
                                                     (вход как игрок)
                                                              │
                                              настоящий Paper-сервер (за границей)
                                                              │
                                             [McTunnel plugin] ← Bukkit канал
                                                              │
                                                 mux → реальные сокеты в интернет
```

- **`internal/mcproto`** — VarInt/VarLong, кадрирование пакетов с порогом
  компрессии, поток AES/CFB8 (для online-mode, milestone 2). Чистый stdlib.
- **`internal/mux`** — мультиплексор: много надёжных потоков поверх одного
  упорядоченного канала, с кредитным окном на поток (нет head-of-line
  блокировки, память ограничена). Клиент открывает нечётные ID, сервер — чётные.
- **`internal/shape`** — token-bucket ограничитель скорости и рандомизация
  размеров пакетов. Честно: это пол, а не готовая маскировка — см. ниже.
- **`internal/mctun`** — склейка mux ↔ custom-payload, offline-вход на сервер,
  connect-заголовок (куда коннектиться), пинованные под 1.20.1 play-IDs.
- **`cmd/mctun-client`** — локальный SOCKS5-прокси + вход на сервер.
- **`server-plugin/`** — Paper-плагин: мост канала в исходящие сокеты.
  Использует только стабильный Bukkit messaging API, поэтому **не зависит от
  версии протокола** (IDs пакетов там не нужны).

## Сборка

Клиент (чистый stdlib, без зависимостей — можно аудитить глазами):

```bash
cd mc-tunnel
go test ./...                 # всё ядро под тестами
go build -o mctun-client ./cmd/mctun-client
```

Плагин (нужен доступ к repo.papermc.io — в этой CI-песочнице он заблокирован,
собирается на обычной машине):

```bash
cd server-plugin
mvn package                   # -> target/McTunnel.jar
```

## Запуск

1. Разверни Paper 1.20.1 на VPS **за пределами страны с блокировками**
   (см. `SERVER-SETUP.md`). Положи `McTunnel.jar` в `plugins/`, запусти.
2. На машине пользователя:

   ```bash
   ./mctun-client --server play.твой-сервер.net:25565 \
                  --user Steve --channel mctunnel:d \
                  --listen 127.0.0.1:1080 --rate-kb 2048
   ```
3. Укажи в браузере/системе SOCKS5-прокси `127.0.0.1:1080`.

Канал (`--channel`) на клиенте и в `config.yml` плагина должен совпадать.

## Честные ограничения

- **Пропускная способность.** Под профилем геймплея реально single-digit
  Mbps. Браузинг, мессенджеры, почта — да. 4K-стриминг спалит статистику и
  смысла не имеет.
- **Шейпинг — это floor, не готовая маскировка.** `shape` убирает самые грубые
  признаки (ровные MTU-пакеты, профиль закачки), но пока НЕ воспроизводит
  временное распределение настоящей игры. Это и есть открытая сложная часть
  задачи, которую в итоге измеряет серьёзный цензор.
- **Свежий сервер уязвим.** Защита от зондирования работает тем лучше, чем
  дольше аптайм и реальнее игроки. Первые недели IP без репутации. План
  прогрева — в `SERVER-SETUP.md`.
- **Online-mode (Mojang-аутентификация) ещё не реализован** — MVP ходит на
  offline-mode сервер. Это снижает «настоящесть». См. дорожную карту.
- **Play-IDs клиента пинованы под 1.20.1.** Другая версия сервера — поправь
  блок констант в `internal/mctun/login.go`. Плагин при этом трогать не нужно.

## Безопасность и правовое

Инструмент предназначен для обхода цензуры — доступа к свободному интернету
там, где его ограничивают. Разворачивай только на серверах и в сетях, которыми
распоряжаешься сам. Правовой статус обхода блокировок и запуска VPN зависит от
твоей юрисдикции — это на твою ответственность.
