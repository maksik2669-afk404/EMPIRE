# Спецификация DSP и SSP платформ (dsp-ssp-spec)

Спроектировать протокол взаимодействия платформ программной закупки рекламы (Demand-Side Platform / DSP) и монетизации издателей (Supply-Side Platform / SSP) по протоколу OpenRTB 2.5/3.0. Скилл охватывает Header Bidding, управление cookie/ID-синхронизацией, обработку бид-реквестов и флор-прайсы (Floor Prices).

## Процесс

1. **Определи архитектуру OpenRTB взаимодействия:** Опиши формирование Bid Request на стороне SSP и обработку Bid Response со стороны подключенных DSP.
2. **Спроектируй Header Bidding и Prebid.js интеграцию:** Параллельный опрос внешних рекламодателей до вызова основного рекламного сервера (Prebid auction timeout 500-800ms).
3. **Настрой алгоритмы оптимизации ставок (Bid Shading & Floor Pricing):** Динамическое управление минимальной ценой показа (Dynamic Floors) на основе исторических данных.
4. **Опиши систему синхронизации пользователей (Cookie/User ID Syncing):** Механизм сопоставления идентификаторов пользователей (Match Table) через прозрачные пиксели.
5. **Заложи мониторинг сетевых задержек и инфраструктуры:** Контроль QPS (Queries Per Second), таймаутов ответа DSP и процента отбракованных ответов.
6. **Сохрани артефакт** в текущей рабочей директории как `dsp-ssp-spec-[контекст].md`.

## Формат вывода

### 1. Спецификация OpenRTB Bid Request / Response

| Поле OpenRTB | Тип данных | Описание и назначение | Пример значения |
| :--- | :--- | :--- | :--- |
| [`id`] | [String] | [Уникальный ID аукциона / запроса] | [`"auc_8f9a2b1c"`] |
| [`imp[].bidfloor`] | [Float] | [Минимальная цена показа (Floor Price в руб/CPM)] | [`150.00`] |
| [`seatbid[].bid[].price`] | [Float] | [Ставка DSP за показ (CPM)] | [`185.50`] |
| [`seatbid[].bid[].adm`] | [String] | [HTML/JS код рекламного креатива] | [`"<iframe src='...'>"`] |

### 2. Спецификация Header Bidding таймлайна

| Этап Header Bidding | Максимальный таймаут | Действие при превышении таймаута |
| :--- | :--- | :--- |
| [Запрос ставок у DSP] | [700 миллисекунд] | [Исключение неответивших DSP из аукциона] |
| [Сравнение ставок в браузере] | [50 миллисекунд] | [Выбор максимальной валидной ставки] |
| [Рендеринг креатива-победителя] | [200 миллисекунд] | [Запасной показ прямого рекламодателя (House Ad)] |

### 3. Метрики эффективности DSP/SSP платформы
- **Bid Win Rate:** Доля выигранных аукционов DSP относительно общего числа отправленных ставок.
- **Match Rate:** Процент успешной идентификации пользователей между SSP и DSP.
- **Average Latency:** Время отклика DSP на входящий Bid Request.
- **Publisher Yield Increment:** Прирост дохода медиа-издателя после внедрения Header Bidding.

## Правила

- Запрещено принимать ставки от DSP с задержкой ответа выше жестко установленного таймаута (Auction Timeout).
- Любой креатив от DSP обязан проходить предварительную автоматическую проверку на вредоносный код и редиректы.
- Архитектура требует обязательной поддержки Cookieless-идентификаторов (First-Party ID / Unified ID 2.0).
- Не допускай передачи незахешированных персональных данных пользователей в теле OpenRTB запросов.
- Максимальный процент расхождений в статистике показов (Discrepancy) между DSP и SSP не должен превышать 5%.
