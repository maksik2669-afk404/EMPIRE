# Масштабирование и раскатка Enterprise продукта (enterprise-rollout)

Спроектировать детальный регламент и архитектуру масштабного развертывания B2B/Enterprise решения на тысячи пользователей в филиальной сети. Скилл обеспечивает бесшовный переход с legacy-систем, управление миграцией данных, минимизацию простоев (Downtime) и поддержку первой линии.

## Процесс

1. **Сформируй план миграции данных (Data Migration Strategy):** Опиши правила очистки, сопоставления полей (Schema Mapping), исторической ретро-выгрузки и сверки контрольных сумм.
2. **Разработай схему канареечного развертывания (Phased Rollout):** Разбей внедрение по филиалам / кластерам (Wave 1: Пилотный регион 5%, Wave 2: 25%, Wave 3: 100%).
3. **Спроектируй протокол отката (Rollback Procedure):** Зафиксируй временные пороги принятия решения об откате (Rollback Window) и автоматические триггеры возврата на старую систему.
4. **Организуй контур поддержки запуска (War Room & Hypercare):** Сформируй дежурную группу L2/L3 инженеров, выделенный канал экстренной связи и SLA реакции < 5 минут.
5. **Настрой панель телеметрии внедрения (Rollout Dashboard):** Мониторинг процента ошибок, нагрузки на серверы, скорости обработки транзакций и активности пользователей.
6. **Сохрани артефакт** в текущей рабочей директории как `enterprise-rollout-[контекст].md`.

## Формат вывода

### 1. План волн развертывания (Rollout Waves)

| Волна запуска | Охват филиалов / пользователей | Длительность | Условия старта (Entry Criteria) | Условия перехода (Exit Criteria) |
| :--- | :--- | :--- | :--- | :--- |
| [Волна 0: Sandbox] | [Тестовая группа ИТ (20 чел)] | [1 неделя] | [Успешные E2E тесты] | [0 критических багов] |
| [Волна 1: Пилот] | [2 региональных филиала (200 чел)] | [2 недели] | [Обучение 100% сотрудников] | [Uptime 99.9%, CSAT > 4.2] |
| [Волна 2: Кластер] | [10 филиалов (1500 чел)] | [3 недели] | [Успех Волны 1 + аудит нагрузки] | [Стабильная работа БД] |
| [Волна 3: Полная] | [Все филиалы (10 000+ чел)] | [4 недели] | [Согласование Steering Committee] | [Выход на плановые SLA] |

### 2. План аварийного отката (Rollback Plan)

| Сценарий инцидента | Триггер отката (Threshold) | Ответственное лицо | Порядок действий при откате |
| :--- | :--- | :--- | :--- |
| [Падение БД / Потеря данных] | [Data Loss > 0.01% транзакций] | [Lead Architect / CTO] | [Остановка трафика, восстановление из бэкапа] |
| [Массовый сбой авторизации] | [Ошибки входа > 5% пользователей] | [Release Manager] | [Переключение DNS на Legacy кластер] |
| [Критическая деградация SLA] | [Задержка ответа API > 3 сек] | [Product Owner] | [Отключение новых модулей через Feature Flags] |

### 3. Метрики эффективности раскатки
- **Rollout Schedule Adherence:** Процент соблюдения плановых дат запуска по волнам.
- **Rollout Defect Density:** Количество дефектов P1/P2 на 1000 активных пользователей.
- **Migration Data Accuracy:** Доля корректно перенесенных записей без расхождений (Target: 99.999%).
- **User Ticket Volume per Wave:** Количество инцидентов поддержки на этапе Hypercare.

## Правила

- Запрещено проводить Enterprise раскатку без предварительно протестированного и утвержденного плана отката (Rollback Plan).
- Каждая волна развертывания обязательно должна сопровождаться периодом усиленной поддержки (Hypercare) длительностью не менее 14 дней.
- При возникновении хотя бы одной ошибки класса P1 (блокировка бизнес-процесса), процесс раскатки немедленно замораживается.
- Не допускай миграции базы данных без создания полной резервной копии (Full Cold Backup) непосредственно перед стартом работ.
- Максимальное допустимое окно технологического перерыва (Downtime Window) должно быть согласовано с бизнесом за 30 дней.
