# Анализ решений Build vs Buy vs Partner (build-buy-partner)

Спроектировать детальный фреймворк принятия стратегического решения: разрабатывать фичу/модуль инхаус (Build), покупать готовое SaaS/Enterprise решение (Buy) или входить в партнерство (Partner). Скилл учитывает TCO (Total Cost of Ownership) на горизонте 3 лет, Time-to-Market, риски Vendor Lock-in и требования к безопасности данных.

## Процесс

1. **Определи стратегическую ценность и Core Competency:** Оцени, является ли создаваемая функциональность ключевым конкурентным преимуществом (Core Moat) или стандартным commodity-сервисом.
2. **Рассчитай 3-летний TCO (Total Cost of Ownership):** Сопоставь затраты на разработку (FTE инженеров + поддержка + инфраструктура) против стоимости лицензий вендора (Implementation fee + Recurring licenses + Tier expansion).
3. **Оцени скорость вывода на рынок (Time-to-Market):** Сравни сроки кастомной разработки MVP против времени интеграции API вендора и согласования Enterprise-контракта.
4. **Проведи аудит рисков безопасности и Vendor Lock-in:** Оцени соответствие 152-ФЗ/GDPR, доступность исходного кода/эскроу, возможность безболезненной миграции данных при смене поставщика.
5. **Сформируй взвешенную матрицу решений (Decision Matrix):** Примени взвешенный скоринг с весами по критериям качества, надежности, масштабируемости и финансовой эффективности.
6. **Сохрани артефакт** в текущей рабочей директории как `build-buy-partner-[контекст].md`.

### 3. Метрики эффективности принятого решения
- **Time to Market Delta:** Разница в месяцах между запуском решения и плановым дедлайном.
- **TCO Variance:** Отклонение фактических расходов от прогнозного 3-летнего бюджета.
- **Vendor SLA Compliance:** Процент соблюдения контрактного SLA поставщиком решений.
- **Engineering Opportunity Cost:** Количество высвобожденных инженерных человеко-месяцев.

## Правила

- Запрещено принимать решение Build для не ключевых (non-core) функций, если на рынке есть зрелое SaaS-решение с TCO на 30% ниже.
- При выборе сценария Buy обязательно должен быть зафиксирован план выхода (Exit Strategy) и процедура миграции данных.
- Оценка любого сценария требует обязательного учета затрат на онбординг, интеграцию API и обучение персонала.
- Если TCO сценария Build превышает 15 млн руб, скилл обязывает провести независимый аудит оценки трудозатрат.
- Максимальный горизонт окупаемости инвестиций в кастомную разработку не должен превышать 24 месяца.
