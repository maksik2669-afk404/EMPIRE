# Глубокий анализ продуктовых метрик и аномалий (metrics-analyzer)

Спроектировать аналитическое расследование продуктовой аномалии (Metrics Deep-Dive / Root Cause Analysis): декомпозиция воронки, сегментационный анализ, когортная динамика, исключение внешних факторов и формулирование корректирующих мер.

## Процесс

1. **Зафиксируй факт и масштаб аномалии метрики:** Опиши точный характер изменения: падение/всплеск целевой метрики относительно базового тренда (Baseline).
2. **Исключи технические сбои и ошибки логирования:** Проверка целостности трекинга событий, сбоев сбора данных, релизов новых версий приложений и обновлений SDK.
3. **Проведи многомерный сегментационный анализ (Slicing & Dicing):** Разрез метрики по платформам (iOS/Android/Web), странам/городам, типам трафика, когортам давности и версиям ОС.
4. **Определи корневую причину аномалии (Root Cause Identification):** Сопоставление с продуктовыми релизами, маркетинговыми кампаниями, действиями конкурентов или сезонностью.
5. **Сформируй план устранения и мониторинга (Action Plan & Guardrails):** Немедленные исправления (Hotfix), план восстановления метрики и настройка алертов.
6. **Сохрани артефакт** в текущей рабочей директории как `metrics-analyzer-[контекст].md`.

## Формат вывода

### 1. Паспорт аналитического расследования аномалии

| Параметр расследования | Данные анализа |
| :--- | :--- |
| **Исследуемая метрика** | **[Конверсия из корзины в успешную оплату (Cart-to-Order CR)]** |
| **Характер аномалии** | **[Падение с 64.2% до 51.8% (-12.4 п.п.) начиная со вторника 10:00]** |
| **Масштаб финансовых потерь** | [Оценочные недополученные продажи ~1.4 млн руб за 48 часов] |
| **Статус расследования** | **[Корневая причина найдена / Hotfix выпущен в продакшн]** |

### 2. Спецификация сегментационного разреза аномалии

| Сегмент анализа | Значение метрики ДО | Значение метрики ПОСЛЕ | Отклонение | Вердикт сегмента |
| :--- | :--- | :--- | :--- | :--- |
| [Платформа: iOS App] | [65.0%] | [64.8%] | [-0.2 п.п.] | [В пределах нормы (Нет проблемы)] |
| [Платформа: Android App] | [63.5%] | [63.1%] | [-0.4 п.п.] | [В пределах нормы (Нет проблемы)] |
| [Платформа: Mobile Web] | [64.1%] | [32.0%] | [-32.1 п.п.] | [КРИТИЧЕСКАЯ АНОМАЛИЯ НАЙДЕНА] |
| [Браузер: Safari Mobile] | [64.5%] | [24.2%] | [-40.3 п.п.] | [ЛОКАЛИЗАЦИЯ: Баг с кнопкой ApplePay] |

### 3. План корректирующих действий (Remediation Plan)
- **Действие 1 (Hotfix):** Исправление бага JS-обработчика клика платежного шлюза в Safari Mobile (Выполнено за 40 минут).
- **Действие 2 (Мониторинг):** Настройка гранулярного алерта в Grafana на падение CR Safari Mobile ниже 55%.

### 4. Метрики эффективности процесса анализа метрик
- **Time to Detect Anomaly (TTD):** Время от возникновения отклонения метрики до срабатывания системы алертинга.
- **Time to Root Cause Identification (TTRC):** Время, затраченное аналитиком на локализацию корневой причины.
- **Revenue Impact Mitigation:** Сумма предотвращенных финансовых потерь благодаря быстрому расследованию.
- **Recurring Anomaly Rate:** Процент повторных инцидентов по одной и той же причине (Target: 0%).

## Правила

- Запрещено делать выводы о причинах падения метрики на основе агрегированных данных без гранулярной сегментации.
- Аналитическое расследование обязано начинаться с верификации корректности сбора и логирования данных.
- Отчет требует обязательного сопоставления аномалии с таймлайном релизов и конфигурационных изменений.
- Не допускай закрытия инцидента без настройки превентивного автоматического алерта в системе мониторинга.
- Максимальное время локализации критической аномалии метрики первого приоритета (P0) не должно превышать 4 часов.
