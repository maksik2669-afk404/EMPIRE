# Проектирование пути гражданина в госсервисах (citizen-journey)

Спроектировать CJM взаимодействия гражданина с государственными цифровыми услугами (Госуслуги, муниципальные порталы, социальные сервисы). Скилл фокусируется на инклюзивности, доступности по ГОСТ/WCAG, сокращении шагов подачи заявлений и прозрачности статусов оказания услуги.

## Процесс

1. **Определи жизненную ситуацию гражданина (Life Situation):** Сформулируй контекст обращения (рождение ребенка, получение льготы, смена паспорта, регистрация бизнеса).
2. **Построй сквозную карту пути (Omnichannel CJM):** Опиши этапы: Осознание потребности -> Поиск услуги -> Заполнение формы -> Межведомственные запросы -> Получение результата.
3. **Оптимизируй сбор данных (Smart Pre-fill):** Минимизируй ручной ввод — используй автоподстановку данных из цифрового профиля гражданина и ведомственных реестров.
4. **Спроектируй инклюзивность и доступность (Accessibility):** Требования для слабовидящих, поддержка экранных дикторов (Screen Readers), простота языка (Plain Language / Ясный язык).
5. **Опиши обработку отказов и апелляций:** Понятное объяснение причин отказа с пошаговой инструкцией исправления ошибок без повторного сбора документов.
6. **Сохрани артефакт** в текущей рабочей директории как `citizen-journey-[контекст].md`.

## Формат вывода

### 1. Карта клиентского пути гражданина (Citizen CJM)

| Этап пути | Действие гражданина | Мысли и барьеры | Работа системы (Backend / СМЭВ) | Решение для оптимизации |
| :--- | :--- | :--- | :--- | :--- |
| [1. Поиск услуги] | [Ввод запроса в поиске] | [Не знает точное бюрократическое название] | [Полнотекстовый поиск + синонимы] | [Подсказка по жизненной ситуации] |
| [2. Заполнение формы] | [Проверка личных данных] | [Страх ошибиться в реквизитах] | [Автозаполнение из Цифрового профиля] | [Zero-entry: подтверждение в 1 клик] |
| [3. Межведомственный обмен] | [Ожидание решения] | [Непонятно, на какой стадии заявка] | [Запросы через СМЭВ в ведомства] | [Push-уведомления о каждом этапе] |
| [4. Получение результата] | [Скачивание документа / QR] | [Нужен ли бумажный оригинал?] | [Генерация электронной подписи (КЭП)] | [Юридически значимый PDF в профиле] |

### 2. Спецификация доступности и понятности (Plain Language & A11y)
- **Уровень читаемости:** Текст написан простым языком без канцеляризмов (индекс Flesch-Kincaid адаптирован для широкой аудитории).
- **Стандарты доступности:** Соответствие ГОСТ Р 52872-2019 / WCAG 2.1 AA (контрастность текста ≥ 4.5:1, навигация с клавиатуры).
- **Экранные сценарии для мобильных устройств:** Адаптация формы под экраны смартфонов с крупными полями ввода.

### 3. Метрики качества государственной услуги
- **Digital Adoption Rate:** Доля заявлений, поданных в электронном виде, от общего объема обращений.
- **First-Time Right Rate (FTR):** Процент заявлений, принятых с первого раза без отказов из-за ошибок заполнения.
- **Average Service Delivery Time:** Фактическое время оказания услуги в днях относительно нормативного регламента.
- **Citizen Satisfaction Index (CSI):** Оценка удовлетворенности качеством предоставления услуги (по шкале 1-5).

## Правила

- Запрещено запрашивать у гражданина документы и справки, которые уже находятся в распоряжении государственных ведомств (Принцип Single Source of Truth).
- Интерфейс подачи заявления обязан соответствовать стандартам доступности WCAG 2.1 AA и ГОСТ для людей с инвалидностью.
- При отказе в предоставлении услуги система требует обязательного указания конкретной причины и ссылки на пункт регламента с инструкцией по исправлению.
- Не используй нерасшифрованные ведомственные аббревиатуры и юридический канцелярит в интерфейсных текстах.
- Максимальное количество шагов в интерактивной форме услуги не должно превышать 5 экранов.
