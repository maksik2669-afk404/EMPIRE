# Проектирование платформы мини-приложений (mini-app-platform)

Спроектировать экосистемную платформу мини-аппов (Web App / Mini Apps внутри Telegram, VK, Госуслуг или корпоративного суперэппа). Скилл охватывает JS Bridge API, безопасность песочницы (Sandbox), аутентификацию, платежный шлюз и документацию для сторонних разработчиков.

## Процесс

1. **Спроектируй архитектуру JS Bridge и SDK:** Опиши методы взаимодействия мини-аппа с нативным контейнером (доступ к камере, геолокации, биометрии, контактам, Haptic feedback).
2. **Заложи модель безопасности и изолированной песочницы (Sandbox):** Ограничение доступа к cookie хост-приложения, защита от XSS, проверка подлинности initData через HMAC-SHA256.
3. **Спроектируй бесшовную авторизацию и платежи:** Авторизация по сессии суперэппа (Single Sign-On) и нативный платежный шлюз (In-App Payments / СБП) без переходов в браузер.
4. **Разработай регламент модерации и песочницу тестирования:** Требования к UI/UX сторонних разработчиков, чеклист безопасности и Developer Console.
5. **Опиши механизмы дистрибуции и виральности:** Каталог мини-аппов, диплинки, шеринг в чаты, контекстные подсказки и пуш-уведомления от мини-аппов.
6. **Сохрани артефакт** в текущей рабочей директории как `mini-app-platform-[контекст].md`.

## Формат вывода

### 1. Спецификация методов JS Bridge SDK

| Метод SDK | Входные параметры | Возвращаемый результат | Необходимые разрешения (Permissions) |
| :--- | :--- | :--- | :--- |
| [`getGeoLocation()`] | [`{highAccuracy: true}`] | [`{lat, lng, accuracy}`] | [Запрос согласия пользователя] |
| [`requestPayment()`] | [`{orderId, amount, currency}`] | [`{status: 'paid', txId}`] | [Доступ к платежному профилю] |
| [`openBiometric()`] | [`{reason: 'Подтвердите вход'}`] | [`{success: true, token}`] | [Наличие биометрии на устройстве] |
| [`shareToChat()`] | [`{text, url, attachment}`] | [`{shared: true, chatId}`] | [Разрешение на шаринг] |

### 2. Модель безопасности и модерации мини-приложений

| Уровень проверки | Что проверяется | Инструмент контроля | Блокирующее условие (Rejection) |
| :--- | :--- | :--- | :--- |
| [Автоматический SAST] | [Уязвимости кода, утечки токенов] | [SonarQube / Сканнеры зависимостей] | [Наличие High/Critical уязвимостей] |
| [Security Audit] | [Проверка валидации HMAC подписи] | [Автотесты песочницы] | [Обход валидации initData] |
| [UX Review] | [Соответствие гайдлайнам, скорость] | [Ручная модерация команды экосистемы] | [Время первой отрисовки (FCP) > 2.5 сек] |

### 3. Метрики эффективности платформы мини-приложений
- **Mini-App DAU / MAU:** Суммарная аудитория всех мини-приложений внутри суперэппа.
- **Developer Ecosystem Growth:** Количество зарегистрированных разработчиков и опубликованных мини-аппов.
- **Bridge API Call Latency:** Среднее время выполнения вызова через нативный JS Bridge.
- **In-App Payment GMV:** Совокупный объем платежей, проведенных через платежный SDK мини-аппов.

## Правила

- Запрещено передавать персональные данные пользователя мини-приложению без его явного подтверждения (Permission Prompt).
- Каждый запрос к бэкенду мини-приложения обязан валидироваться по криптографической HMAC-подписи хост-контейнера.
- Платформа требует обязательной изоляции DOM и хранилища мини-приложения от контекста родительского приложения.
- Не допускай публикации мини-приложений, не адаптированных под мобильные жесты и темную/светлую тему контейнера.
- Максимальный размер бандла мини-приложения для быстрой загрузки не должен превышать 5 Мб.
