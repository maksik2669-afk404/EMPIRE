# Спецификация функций на базе искусственного интеллекта (ai-feature-spec)

Спроектировать продуктовые требования к фичам на базе классического ML и генеративного AI (GenAI / LLM). Скилл охватывает точностные метрики (Precision/Recall, F1), обработку галлюцинаций, фолбэки (Graceful Degradation), латентность инференса и интерфейс обратной связи.

## Процесс

1. **Определи бизнес-цель и критерии качества ML-модели:** Зафиксируй целевые бизнес-метрики и точностные метрики (Precision, Recall, ROC-AUC, BLEU/ROUGE).
2. **Спроектируй поведение при низкой уверенности (Confidence Thresholds):** Раздели предсказания модели на зеленую (Авто-применение ≥ 0.85), желтую (Подтверждение человеком 0.50-0.85) и красную зону (Fallback на эвристику < 0.50).
3. **Опиши защитные барьеры и обработку сбоев (Guardrails & Fallback):** Поведение системы при падении AI-модели или превышении таймаута инференса (Circuit Breaker).
4. **Спроектируй UX обратной связи (Human-in-the-Loop Feedback):** Кнопки 👍/👎, причины неудовлетворительного ответа, отправка исправлений в обучающий датасет.
5. **Заложи мониторинг дрейфа данных (Data & Concept Drift):** Регулярный пересчет метрик качества на свежем проде и алерты при деградации точности.
6. **Сохрани артефакт** в текущей рабочей директории как `ai-feature-spec-[контекст].md`.

## Формат вывода

### 1. Матрица порогов уверенности (Confidence Score Policy)

| Зона уверенности | Диапазон Score | Поведение в интерфейсе | Обработка ошибок |
| :--- | :--- | :--- | :--- |
| [Высокая уверенность] | [Score ≥ 0.85] | [Мгновенное применение без вопросов к юзеру] | [Возможность Undo в течение 10 сек] |
| [Средняя уверенность] | [Score 0.50 - 0.84] | [Показ как рекомендации с кнопкой 'Применить'] | [Ручной выбор из 3 альтернатив] |
| [Низкая уверенность] | [Score < 0.50] | [Скрытие AI-блока, переключение на эвристику] | [Тихий сбор лога для дообучения] |

### 2. Спецификация защитных барьеров и Fallback-сценариев

| Сбой AI сервиса | Таймаут срабатывания | Fallback-механизм | Коммуникация с пользователем |
| :--- | :--- | :--- | :--- |
| [Превышение задержки LLM] | [> 3.0 секунд] | [Переключение на легковесную локальную модель] | [Анимация генерации без зависания] |
| [Галлюцинация / Невалидный JSON] | [Сбой парсинга схемы] | [Авто-повтор запроса с температурой 0.0] | [Показ сохраненного шаблона] |
| [Срабатывание Guardrail фильтра] | [Токсичный/запрещенный запрос] | [Блокировка ответа модели] | ['Запрос не может быть обработан'] |

### 3. Метрики эффективности AI фичи
- **Model Acceptance Rate:** Доля рекомендаций/генераций AI, принятых пользователями без правок.
- **Inference Latency (p95):** Время генерации ответа модели под нагрузкой.
- **Correction / Edit Rate:** Процент сгенерированного контента, отредактированного пользователем вручную.
- **Feature ROI / Unit Cost:** Стоимость одного вызова инференса относительно принесенной бизнес-ценности.

## Правила

- Запрещено выпускать AI-фичу в прод без явного механизма фолбэка (Fallback) при недоступности модели.
- Интерфейс обязательно должен содержать визуальную маркировку того, что контент сгенерирован искусственным интеллектом.
- Любая генеративная модель требует обязательной валидации выходного формата по строгой JSON-схеме.
- Не используй инференс тяжелых моделей для простых задач: эвристики и правила всегда имеют приоритет по скорости.
- Максимальный бюджет стоимости API-токенов на одного пользователя в месяц должен быть жестко ограничен лимитом.
