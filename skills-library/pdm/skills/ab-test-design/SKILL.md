# Дизайн и проведение A/B экспериментов (ab-test-design)

Спроектировать дизайн A/B/n эксперимента: расчет размера выборки (Sample Size), минимально обнаруживаемого эффекта (MDE), выбор целевой метрики, балансирующих guardrail-метрик, проверка на SRM и статистический анализ (t-test / Mann-Whitney / Bootstrap).

## Процесс

1. **Сформулируй проверяемую статистическую гипотезу:** Нулевая гипотеза H₀ (нет различий) vs Альтернативная гипотеза H₁ (вариант B дает статистически значимый прирост целевой метрики).
2. **Определи метрики эксперимента:** Первичная целевая метрика (Primary Metric), вторичные диагностические метрики и ограничивающие метрики (Guardrails: Churn, Латенси, Ошибки).
3. **Рассчитай размер выборки и длительность:** Расчет выборки на вариант с учетом мощности теста (1 - β = 80%), уровня значимости (α = 0.05) и минимального ожидаемого эффекта (MDE).
4. **Настрой правила сплитования и защиту от SRM (Sample Ratio Mismatch):** Хэширование User ID (MurmurHash3), равномерное распределение 50/50, Chi-Square тест на проверку SRM.
5. **Опиши процедуру подведения итогов и принятия решений:** Расчет p-value, доверительных интервалов и правила раскатки победителя (Rollout Plan).
6. **Сохрани артефакт** в текущей рабочей директории как `ab-test-design-[контекст].md`.

## Формат вывода

### 1. Паспорт дизайна A/B эксперимента (Experiment Spec)

| Параметр эксперимента | Значение / Настройка | Обоснование |
| :--- | :--- | :--- |
| **Проверяемая гипотеза (H₁)** | [Липкая кнопка 'Купить' увеличит CR чекаута на +5%] | [Устранение трения скролла на мобильных устройствах] |
| **Целевая метрика (Primary)** | [PDP-to-Checkout Conversion Rate (%)] | [Прямой показатель конверсионности карточки товара] |
| **Ограничивающие Guardrails** | [Crash Rate ≤ 0.01%, Average Order Value (AOV)] | [Защита от технических сбоев и снижения среднего чека] |
| **Размер выборки на вариант** | [35 000 уникальных пользователей на группу] | [Обеспечение детекции MDE +4.0% при α = 0.05, β = 0.20] |
| **Длительность эксперимента** | [14 календарных дней (2 полных недели)] | [Учет эффекта дня недели и недельной сезонности] |
| **Единица рандомизации** | [User ID (Авторизованные) / Device ID (Гости)] | [Исключение эффекта переключения между вариантами] |

### 2. Спецификация проверки на смещение сплита (SRM Check)
- **Метод проверки:** Тест согласия Пирсона (χ² Chi-Square test).
- **Пороговое значение:** Если p-value < 0.001, эксперимент признается невалидным (SRM), результаты аннулируются, проводится аудит системы сплитования.

### 3. Метрики эффективности экспериментирования
- **Statistical Power (1 - β):** Мощность теста (не менее 80%).
- **Minimum Detectable Effect (MDE):** Минимальный прирост метрики, который тест способен надежно зафиксировать.
- **Experiment Decision Velocity:** Скорость подведения итогов и раскатки на 100% базы после завершения теста.
- **Novelty Effect Degradation:** Изменение эффекта через 30 дней после полной раскатки победителя.

## Правила

- Запрещено подглядывать в результаты и преждевременно останавливать A/B тест до набора расчетного размера выборки (Peeking Problem).
- Эксперимент обязан длиться не менее 14 полных календарных дней для исключения влияния эффекта дня недели.
- При обнаружении статистического смещения выборки (SRM p < 0.001) результаты теста подлежат немедленной отмене.
- Не допускай одновременного запуска тестов на одной и той же когорте без взаимной изоляции трафика (Mutual Exclusion).
- Каждый A/B тест обязан иметь минимум 2 ограничивающие Guardrail метрики для защиты выручки и стабильности.
