# Проектирование петель устойчивого роста (growth-loop)

Спроектировать самоподдерживающиеся продуктовые петли роста (Growth Loops) взамен линейных маркетинговых воронок: виральные петли (Viral Loops), контентные петли (UGC/SEO Loops), финансовые петли (Paid Reinvestment Loops) и продуктовые фидбек-лупы.

## Процесс

1. **Определи тип петли роста для продукта:** Выдели доминирующий механизм: Viral Loop (Пригласи друга), Content Loop (Пользователь создал контент -> Индексация в поиске -> Новый пользователь), Paid Loop (LTV генерирует бюджет на маркетинг).
2. **Разложи петлю на 4 ключевых шага (Input -> Action -> Output -> Reinvestment):** Опиши каждый переход цикла и механизм передачи ценности следующей когорте.
3. **Замерь время цикла петли (Loop Cycle Time):** Оптимизируй скорость прохождения одного полного оборота петли (чем быстрее оборот, тем выше экспоненциальный рост).
4. **Устрани трение на каждом шаге петли (Loop Friction):** Упрости расшаривание, введи двусторонние инсентивы, автоматизируй публикацию контента.
5. **Сформируй математическую модель роста:** Расчет вирального коэффициента (K = i × c) и мультипликатора базы пользователей.
6. **Сохрани артефакт** в текущей рабочей директории как `growth-loop-[контекст].md`.

| Параметр формулы | Обозначение | Текущее значение | Целевое значение | Влияние на рост |
| :--- | :--- | :--- | :--- | :--- |

### 3. Метрики эффективности Growth Loop
- **K-Factor (Viral Coefficient):** Среднее количество новых привлеченных пользователей на одного активного пользователя.
- **Viral Cycle Time:** Среднее время от регистрации первого пользователя до регистрации приглашенного им друга.
- **Compounded Organic Growth:** Процент новых пользователей, пришедших через внутренние петли без затрат на рекламу.
- **Loop Retention Lift:** Прирост удержания когорты пользователей, вовлеченных в совместную работу.

## Правила

- Запрещено проектировать виральные петли с односторонней выгодой: ценность должна быть очевидна и отправителю, и получателю.
- Любая контентная петля обязана поддерживать индексацию поисковыми роботами и генерацию OpenGraph мета-тегов.
- При падении коэффициента K < 0.2 механика требует полного пересмотра триггеров и точек контакта.
- Не допускай навязчивого спама контактам из адресной книги без явного ручного выбора пользователем.
- Максимальное время полного цикла одного оборота виральной петли не должно превышать 7 дней.
