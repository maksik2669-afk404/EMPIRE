# Стратегия региональной адаптации и локализации сервисов (localization-strategy)

Спроектировать стратегию адаптации цифровых продуктов под региональную специфику, национальные языки, локальное законодательство и особенности инфраструктуры субъектов РФ или зарубежных рынков. Скилл обеспечивает доступность для всех категорий пользователей независимо от региона.

## Процесс

1. **Проанализируй региональную и языковую специфику:** Выдели требования к мультиязычности (национальные языки регионов), особенностям регионального законодательства и нормативных актов.
2. **Спроектируй архитектуру интернационализации (i18n):** Вынос всех строк в локализационные файлы (JSON/gettext), поддержка динамического плюрализма и форматирования дат/валют.
3. **Адаптируй под региональные особенности связи:** Оптимизация размера приложения и кэширования для регионов с нестабильным 2G/3G покрытием (Offline-first architecture).
4. **Организуй процесс локализационного тестирования (L10n QA):** Проверка верстки при разной длине фраз, корректности терминов и культурных контекстов носителями языка.
5. **Сформируй план поддержки региональных интеграций:** Интеграция с локальными платежными системами, региональными банками и адресными классификаторами (ФИАС/КЛАДР).
6. **Сохрани артефакт** в текущей рабочей директории как `localization-strategy-[контекст].md`.

### 2. Спецификация i18n стандартов и архитектуры
- **Формат хранения переводов:** Единые строковые ключи в формате `namespace.feature.element_type` (например, `auth.login.button_submit`).
- **Форматирование данных:** Использование стандартов ICU MessageFormat для валют, чисел, телефонных масок и склонений числительных.
- **Поддержка низкой скорости сети (Low-Bandwidth Mode):** Сжатие изображений в WebP, отключение тяжелых анимаций, сжатие payloads до < 50 Кб.

### 3. Метрики эффективности локализации
- **Regional Adoption Rate:** Процент проникновения сервиса среди целевой аудитории региона.
- **Language Switch Ratio:** Доля пользователей, выбирающих национальный язык интерфейса.
- **Localization Defect Count:** Количество багов верстки (обрезка текста, отсутствие перевода) на один релиз.
- **Offline Sync Success Rate:** Процент успешных синхронизаций данных при восстановлении интернет-соединения.

## Правила

- Запрещено хардкодить текстовые строки, валюты и форматы дат непосредственно в кодовой базе приложения.
- Каждый локализованный интерфейс обязательно должен пройти проверку носителями языка (Native Speaker Review).
- Архитектура сервиса требует строгого соблюдения локального законодательства о хранении персональных данных граждан в целевой юрисдикции.
- Не допускай верстки без запаса места: длина переведенных строк может превышать оригинал на 30-40%.
- Все критические сценарии в регионах с нестабильной связью обязаны поддерживать сохранение черновиков в локальном хранилище (Offline storage).
