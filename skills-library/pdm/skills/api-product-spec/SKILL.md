# Спецификация API как продукта (api-product-spec)

Спроектировать публичный или B2B партнерский API (REST / GraphQL / gRPC / Webhooks): контракты OpenAPI 3.0, версионирование, авторизация по OAuth2/API-ключам, рейтримиты (Rate Limiting) и портал разработчика (DevPortal).

## Процесс

1. **Определи ключевые сценарии интеграции (API Use Cases):** Опиши, какие бизнес-задачи внешние разработчики будут решать через API и какова модель монетизации (Free Tier, Pay-per-Call, Subscription).
2. **Спроектируй структуру эндпоинтов и схему данных:** Именование ресурсов (RESTful Resource Naming), методы (GET, POST, PUT, DELETE, PATCH), коды ответов HTTP и схемы ошибок RFC 7807.
3. **Настрой политики безопасности и авторизации:** Аутентификация через Bearer Tokens (JWT), гранулярные скоупы доступа (Scopes: `read:orders`, `write:orders`), HMAC-подпись вебхуков.
4. **Спроектируй систему лимитов и квот (Rate Limiting & Quotas):** Лимиты запросов в секунду/минуту (RPS/RPM) с возвратом заголовков `X-RateLimit-Remaining` и кодом `429 Too Many Requests`.
5. **Опиши стратегию версионирования и Deprecation Policy:** Семантическое версионирование (SemVer), поддержка старых версий не менее 12 месяцев после объявления об устаревании.
6. **Сохрани артефакт** в текущей рабочей директории как `api-product-spec-[контекст].md`.

## Формат вывода

### 1. Спецификация эндпоинтов REST API

| Метод и URL эндпоинта | Назначение | Необходимый Scope | Пример успешного ответа | Коды ошибок |
| :--- | :--- | :--- | :--- | :--- |
| [`GET /v1/orders`] | [Получение списка заказов с пагинацией] | [`orders:read`] | [`{items: [...], next_cursor: "xyz"}`] | [401, 403, 429] |
| [`POST /v1/orders`] | [Создание нового заказа] | [`orders:write`] | [`{id: "ord_123", status: "created"}`] | [400, 401, 422] |
| [`POST /v1/webhooks`] | [Подписка на события вебхуков] | [`webhooks:manage`] | [`{id: "wh_456", url: "https://..."}`] | [400, 403] |

### 2. Спецификация Rate Limits и тарифных квот

| Тарифный план API | RPS лимит (Burst) | Месячная квота запросов | Цена за 1000 запросов сверх квоты |
| :--- | :--- | :--- | :--- |
| [Starter (Бесплатный)] | [5 запросов/сек] | [10 000 запросов/мес] | [Блокировка 429] |
| [Pro Tier] | [50 запросов/сек] | [1 000 000 запросов/мес] | [15 руб / 1000 вызовов] |
| [Enterprise] | [Custom (> 200 RPS)] | [Безлимит по контракту] | [Индивидуальный биллинг] |

### 3. Метрики эффективности API продукта
- **Time to First Hello World (TTFHW):** Время от регистрации разработчика до первого успешного 200 OK вызова API.
- **API Error Rate (4xx vs 5xx):** Доля клиентских и серверных ошибок в общем потоке вызовов.
- **p99 Latency:** Время ответа эндпоинтов API под пиковой нагрузкой.
- **Active Developer API Keys:** Количество активных интеграций за последние 30 дней.

## Правила

- Запрещено вносить несовместимые ломающие изменения (Breaking Changes) без выпуска новой мажорной версии API.
- Каждый эндпоинт мутации данных (POST/PUT) обязан поддерживать заголовок идемпотентности (Idempotency-Key).
- Спецификация API требует обязательного соответствия формату OpenAPI 3.0 / Swagger.
- Не используй нестандартные форматы ошибок: все ошибки обязаны соответствовать стандарту RFC 7807 (Problem Details).
- Максимальное время ответа API эндпоинтов для чтения не должно превышать 250 миллисекунд (p95).
